# Sudo Code v0.2.22

## Fixed

- Continuing a saved or forked conversation no longer duplicates tool results
  stored in user messages. This could cause Opus and other Anthropic-compatible
  models to reject the request with an unexpected or duplicate `tool_use_id`.
- The shared request boundary reconciles interrupted calls and unmatched results
  before contacting a model, including after a model switch. Existing outputs
  are retained as historical context, while structured session records remain
  intact for replay and `/undo`. Recovery never reruns an earlier tool.
- Valid tool batches and conversation prefixes remain unchanged, including
  parallel calls with results stored in both supported message roles.

The repair applies to the CLI and ACP clients, including SudoWork desktop and
WebUI. No model-specific retry or conversation reset is required.
