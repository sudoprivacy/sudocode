# Sudo Code v0.2.10

## Fixed

**Compaction failures preserve conversation history.** API errors, invalid summaries,
cancellation, and persistence failures leave the original transcript available for
retry. If compaction is required to continue, the agent stops rather than running
without its task context. Optional post-turn failures retain the completed response
and show a notice. Sessions with an existing compaction record but empty history
are rejected.

**Custom deployment IDs use their configured token limits.** Compaction uses the
active provider-facing model ID rather than a configuration alias or a model saved
in an older session. Full deployment IDs, including names containing `/`, take
precedence when looking up limits. This fixes summaries requesting too many output
tokens from custom and internal deployments.

## Improved

- Prune oversized tool output before requesting a summary, preserving its beginning
  and end while keeping ToolSearch data intact.
- Consolidate earlier checkpoints with newer history instead of accumulating old
  summaries. Preserve recent messages by token budget and keep tool exchanges paired.
- Bound summaries to 8,192 output tokens or the model's smaller configured limit;
  reject empty, truncated, tool-calling, and non-shrinking replacements.
- Share text completion transport between main agents and subagents, including
  OpenAI-compatible providers, with a standard summary fallback when needed.
- Archive the original transcript before atomically saving the replacement. Clear
  obsolete context-window counts without clearing token or cost totals.

## Validation improvements

Windows compaction mocks explicitly restore blocking socket reads before applying
timeouts. Tool-registry tests synchronize access to shared environment settings,
and the co-host end-to-end harness pins its host entry to IPv4.

## Notes

Pre-compaction archives remain next to the session and are not automatically
pruned. Private Apeiron deployments were not directly accessible for validation;
the model-ID and limit regressions were verified using local HTTP providers.
