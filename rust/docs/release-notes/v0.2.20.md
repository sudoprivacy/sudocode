# Sudo Code v0.2.20

## Added

- `nexusd-cohost` can run Sudo Code agents inside the Nexus cluster daemon. Co-hosted sessions, sub-agents, plans, todos, memory, and mailboxes use the session's filesystem backend, so agents can persist state and discover peers across nodes. The daemon has its own `nexusd-cohost-v*` release tags and is not bundled with the CLI release.
- `scode cache stats` reports cache usage and the reasons cached prefixes break. Subscription requests can keep eligible Anthropic cached prefixes for one hour.
- `WebSearch` and `WebFetch` are available as core tools without a `ToolSearch` reveal. Other deferred tools are revealed together on the first `ToolSearch` call.
- In the interactive CLI, Up can take the newest queued human input back for editing without consuming queued agent-to-agent messages.

## Changed

- CLI sessions can access the host filesystem from its root instead of being limited to the launch directory and configured additional mounts. Host-side execution and storage follow the same backend contracts used by co-hosted agents.
- Nexus A2A connections use an endpoint and credential instead of the previous multi-option configuration. The live harness uses authenticated connections.
- Spawned sub-agents have their own stable agent names, inherit the parent's permission mode and filesystem backend, and no longer require a task template. The agent list discovers addressable peers through the mailbox rather than local disk.
- Extended thinking is rendered in the CLI instead of being discarded. The static `NEXUS_A2A_PEER` hint was removed in favor of dynamic discovery.

## Fixed

- An agent's prose reply reaches the sender when the agent did not explicitly send a message; automatic replies are bounded to one hop. Presence and directory creation work across the Nexus VFS backend, and failed presence probes are surfaced instead of being mistaken for absent agents.
- ACP restores interrupted tool results before continuing a resumed turn.
- Session cache accounting records every request and distinguishes a discarded prefix from a reused one. Stream usage is recorded at the logical end of a message.
- Mailbox delivery and peer discovery handle backend paths and Windows verbatim paths consistently; dead PIDs are rejected by `send`.
- Co-hosted agents report unsupported spawn configurations and unavailable cron tools instead of silently accepting them.

## Validation

This release adds and strengthens tests for co-hosted session persistence and cross-node discovery, authenticated A2A messaging, cache accounting, resumed ACP tool results, and interactive PTY behavior. The co-host artifact also has independent release checks for its embedded version provenance and platform size budgets.
