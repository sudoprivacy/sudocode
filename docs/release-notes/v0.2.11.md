# Sudo Code v0.2.11

## Added

**Context maintenance is visible while it runs.** Compaction now announces itself
over ACP on the standard operation lifecycle (`context_compaction`), carrying the
trigger — manual, pre-turn, in-turn budget, provider rejection, or post-turn — and
estimated token counts before and after. It is an engine-owned operation, never a
tool offered to the model. Clients that render it show a live "compacting" step
instead of silence; older clients that ignore the event behave exactly as before.
Cancelling during compaction reports cancellation, not success.

## Changed

**A failed compaction now fails the run.** Post-turn maintenance failures used to
be swallowed: the run reported success and queued work continued. A terminal
compaction failure now ends the prompt with an error, even when answer text has
already streamed, and stops further model and tool work. Conversation history is
preserved in every failure path, so the turn can be retried.

## Fixed

**Long checkpoints no longer abort the task.** Compaction could hit its 8,192-token
output limit mid-checkpoint and fail with `compaction summary was truncated at the
output limit`. Summaries now target 8,000 tokens with a 12,000-token generation
ceiling, keeping any smaller model output limit. Both standard and cache-preserving
compaction use this policy.

**Compaction failures read as one sentence.** The terminal error wrapped an
already-formatted error a second time, so the message repeated its own prefix and
its "history preserved" tail. Each now appears once, and a rejected summary or a
failed save reports the stage that actually failed instead of naming itself an API
error.

**`--print` no longer hangs on an inherited stdin pipe.** A non-interactive run
whose stdin is an open pipe with no data waited forever; it now proceeds once the
first-byte deadline passes.

**One conversation stays on one account.** Requests carry `metadata.user_id`, so a
conversation is not spread across accounts by the provider.

**Subagent parity with the parent session.** Subagents inherit the parent's model
and reasoning effort; only forks inherit thinking configuration. Subagent requests
carry cache control again — without it every subagent turn was billed uncached.

**A vanishing directory entry no longer voids the listing.** A file removed while a
directory is being read is skipped instead of failing the whole call.

**Untrusted A2A content stays inert.** Harness reminders no longer trail user text,
and peer-supplied markup is neutralized at the point of use.

## Improved

- Tool cards: one canonical label across running and completed states, bodies
  wrapped to the frame width, a running card in amber distinct from success green,
  and identity fields from the call input shown on completed cards.
- Scrollback: paste placeholders are expanded in the echo, multi-line echoes indent
  their continuation lines, and restored history is replayed to scrollback when the
  REPL resumes.
- `pid_status` (the agent process table) is separate from `TaskGet` / `TaskList`
  (the to-do registry); the `TaskStop` / `TaskOutput` aliases are gone.
- Dependency: nexus-vfs pinned to v0.7.7.

## Validation

Live and mock CLI integration suites were stabilized: the co-host harness picks and
reports its own image, TLS posture comes from the harness rather than each test, and
one `ToolInputRegistry` is shared by the live and replay render paths.

The compaction lifecycle was verified against a real `scode acp` process driven by a
deterministic OpenAI-compatible endpoint, including the post-turn path where the
operation lands after the answer has streamed, and a permanent summarizer failure.
No paid model call is involved in that coverage.
