# Sudo Code v0.2.12

## Added

**Session listings say what the session was about.** The session command, the
picker and the `--resume` list now show a session's compacted summary instead of
a bare timestamp, falling back to the first user prompt for a session that has
never been compacted. Summaries are truncated to a single line, so a long list
stays scannable.

## Changed

**One `TodoWrite` replaces the four-tool checklist.** `TaskCreate` / `TaskUpdate`
/ `TaskGet` / `TaskList` are gone, replaced by a single `TodoWrite` that takes the
whole list and replaces the previous one — the Claude Code model, with no per-item
id and no partial update. The concept is named `todo` throughout, in prompts and
in the tool surface. Agents written against the old `Task*` names must send the
full list to `TodoWrite` instead.

## Fixed

**`--print` no longer hangs on Windows either.** v0.2.11 fixed this on Unix only:
its readiness check used `poll`, while every other platform reported "readable"
unconditionally and went straight into a read that never returns. So on Windows a
non-interactive run whose stdin is an inherited pipe — a pipe a parent opened and
then never writes to and never closes, which is what a harness, a CI step or a
background job looks like — still parked forever, and silently, because the
"no stdin data received" warning lived on a branch Windows could not reach.
Measured on the released 0.2.11: `sleep 20 | scode --print` returned only after
21s, against 1s for `< /dev/null`. It now serves the 3s first-byte deadline and
says why it moved on. Readiness comes from `PeekNamedPipe`; a console or a file
redirect, which cannot park, reads as before.

**The todo list survives compaction.** `TodoWrite` has no read tool — the model
relies on the list being in its context and re-sends it whole on every call.
Compaction replaced those calls with prose, so the list was effectively lost
across the boundary and came back lossy or empty. It is now carried across.

**Tool cards render from one code path.** Staging and completed cards were two
implementations that had drifted: Grep and Glob dropped their pattern on the
completed card, so you could not tell what had been searched, and Edit had two
different diff renderers, one of which showed only the first line of the old text.
Both now come from a single extractor.

**A resumed transcript looks like the live one.** Restored user messages rendered
with a ` › ` prefix, a code-background block and a full-width rule above and
below; a live session shows a submitted message as a plain `❯` prompt line. The
rules and the styled echo are gone and the prompt glyph is shared, so the same
scrollback survives `/exit` and `--resume` unchanged.

## Improved

- The live A2A suite now survives a real multi-node quorum and either auth
  posture. Eight sites polled non-blocking immediately after a send, which is
  readable only once raft *applies* the frame — invisible against a
  single-voter loopback daemon, and a flake against a genuine cluster.
- Todo completion counting no longer depends on the process-global todo store.
  That store is bound once per process, so its state leaked between tests in a
  single test binary and made the count order-dependent — a Windows-only CI
  flake. Completions are recorded directly and de-duplicated by the verification
  watcher, which it already did. No change in behaviour for a running agent.
- `stdin-peek`: a new crate holding the workspace's only `unsafe`. The root sets
  `unsafe_code = "forbid"` and every other crate opts in, so the one FFI call
  that Windows readiness needs is isolated where it can be reviewed on its own
  rather than weakening the lint everywhere.

## Validation

The piped-stdin deadline is covered by an integration test that drives the real
binary with a real pipe, on Linux, macOS and Windows as part of
`cargo test --workspace`. A unit test could only inject a fake readiness
predicate — proving the surrounding logic and nothing about either platform's
check, which is the half where the bug lived — and a PTY test cannot reach the
path at all, because a terminal stdin returns early. The test was confirmed to
fail before the fix: with the Windows arm restored, it parked for the full 60s
observation window.
