# Sudo Code v0.2.25

## Fixed

- Compaction now checks the complete replacement history against the next
  request's safe budget and a maximum 50% retained-history target, with 30% as
  the preferred target. Protected messages, tool exchanges, Todo state and
  provider reservations count toward the allowance. Rejected checkpoints are
  never installed; retries share bounded summary and HTTP-attempt limits, and
  failed or cancelled compaction preserves the source history. CLI and ACP
  report the result and refresh context occupancy after compaction and resume.
  This includes the adaptive-thinking output-reservation correction from #922.
- OpenAI-compatible responses accept both current vLLM `reasoning` and legacy
  `reasoning_content` fields in SSE, JSON fallback and non-streaming responses.
  Thinking stays separate from the final answer and is consumed only once when
  both fields are supplied. Azure inline-reasoning handling is preserved (#930).
- Managed agents use their own authorization subject for kernel-backed file
  metadata and typed entry creation. Denied or unavailable remote reads remain
  errors, so append cannot mistake them for missing files and replace existing
  contents. Glob discovery rechecks access and caches metadata for sorting
  (#927).
- Parallel prompt-test fixtures use unique paths, preventing one test from
  deleting another test's workspace on macOS (#930).

## Validation scope

The component PRs include controlled PTY/ACP, HTTP integration and real-kernel
authorization regressions. Compaction budgets are local token estimates, and
protected complete exchanges can prevent the nominal target from being met;
such a history does not receive a weaker checkpoint. The earlier real-model
compaction comparison does not establish a statistical improvement in
first-summary success. Final-head live compaction attempts were blocked by
upstream availability errors.

Actual intranet GLM/vLLM traffic and deployment have not been verified. Remote
metadata authorization also requires the matching Nexus host fixes; the pinned
nexus-vfs v0.8.4 host does not yet enforce Stat/Readdir metadata authorization.
This scode release does not update a Nexus host or deploy Apeiron.
